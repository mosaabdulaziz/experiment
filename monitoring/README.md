# IRIS monitoring stack

Prometheus + Grafana + NVIDIA DCGM exporter + node exporter for the
DeepStream sidecar's per-stage telemetry and the GPU it runs on.

```
docker compose up -d prometheus grafana dcgm-exporter node-exporter
```

- **Grafana** → http://localhost:3000 (default `admin` / `admin`, change on
  first login). The **"IRIS — pipeline & GPU"** dashboard is provisioned
  automatically (folder `IRIS`), with panels for:

  - **DCGM (GPU):** utilization, **decode utilization** (NVDEC — the binding
    resource per `BOTTLENECKS.md`), memory used, temperature, power.
  - **Sidecar pipeline:** per-stage busy% (`probe`, `publish`, `recognizer`,
    `upload`, `rotation`), GPU-element busy% (`gpu.decode.<cam>`,
    `gpu.infer.pgie`, `gpu.infer.sgie_face`, `gpu.jpeg`), per-call average ms,
    per-camera analysis rate (`fps_<id>`), publisher drops/pending,
    analysis-branch mux queue fill, and the face-SGIE mode flag.
- **Prometheus** → http://localhost:9090 (scrapes the sidecar on `:9100`,
  dcgm-exporter on `:9400`, node-exporter on `:9100`).

## Enabling the sidecar metrics

The exporter only runs when the sidecar's telemetry is on (it shares the same
accumulators as the `[telemetry]` log lines):

```yaml
# perception/pipeline/sidecar.yaml
telemetry_enabled: true
telemetry_prometheus_port: 9100   # default; one server per sidecar process
```

then `docker compose restart deepstream-sidecar`. The host mirror of the
metrics port is `http://localhost:9101/metrics` (base service only — shard
replicas are scraped on the compose network, no host port).

The same numbers also appear in the `[telemetry]` log lines every
`telemetry_interval` seconds; the dashboard busy% values are identical to
those lines, so what you see in Grafana matches the benchmark harness
(`benchmarks/stream_capacity.py --telemetry`) exactly.

## Metrics

| Metric | Meaning |
|---|---|
| `iris_stage_busy_percent{stage}` | Stage wall-clock as % of the window (thread utilization) |
| `iris_stage_avg_ms{stage}` | Stage average wall-clock per call |
| `iris_stage_total_ms{stage}` | Stage accumulated wall-clock in the last window |
| `iris_stage_samples_total{stage}` | Total stage call count (counter) |
| `iris_gauge{name}` | Sampled gauges: `publisher_pending`, `publisher_drops`, `segment_uploader_pending`, `recognition_pending`, `sgie_mode`, `mux_queue_<n>`, `fps_<cam-id>` |
| `DCGM_FI_DEV_*` | GPU hardware metrics from dcgm-exporter (`DCGM_FI_DEV_GPU_UTIL`, `DCGM_FI_DEV_DEC_UTIL`, `DCGM_FI_DEV_FB_USED`, `DCGM_FI_DEV_GPU_TEMP`, `DCGM_FI_DEV_POWER_USAGE`, ...) |

## Sharding

With `--profile shards`, each sidecar replica exports its own `/metrics` on
`:9100` in-container; Prometheus has static targets for
`deepstream-sidecar{-1,-2}` and labels them by `shard`. Targets for replicas
that aren't running show as DOWN — they don't affect the other scrapes.

## Scale run: system health dashboard

`scripts/scale13_deploy.sh mon up` (also part of `up`) starts Prometheus, Grafana, node-exporter and
`iris-exporter` from `docker-compose.scale-monitoring.yml`. Open **`https://<ui host>:<port>/grafana/`**
(dashboard **IRIS - system health**, anonymous viewer, dark). It is generated by
`monitoring/grafana/build_scale_dashboard.py` (thresholds are in that file; edit, rerun, `sync`).

| Source | What | Where it comes from |
|---|---|---|
| GPU | core, NVDEC, NVENC (+sessions), memory, temperature, power, clocks, throttle reasons, PCIe, ECC | `iris-exporter` via NVML |
| Cameras | input alive (go2rtc), player alive, silence, fps (0 when dead), stall restarts, bitrate | exporter + sidecar gauges |
| Pipeline | stage busy % / ms, analysis queue fill, publisher drops, Redis memory / streams | sidecar `/metrics`, exporter |
| VLM / association | backlog, in flight, answer time, outcomes, errors, open tracks, pending verdicts | sidecar gauges `vlm_*`, `mtmc_*` |
| Platform | feed backlog, ready, events by status, newest sighting age, push failures, stale drops | exporter, app `/metrics` |
| Host | containers (up, CPU, memory, restarts, OOM), CPU, memory, disk free (data and footage) | exporter, node-exporter |

Panels turn yellow / red at the thresholds (e.g. GPU 85 / 95 %, NVDEC 80 / 95 %, camera silence 5 / 30 s,
VLM backlog 5 / 15, platform backlog 50 / 500, disk free 15 / 5 %). Not available: per-camera decode
counts (the sidecar has no decode probes in this config), so frame loss shows as fps below the source rate.
